## 2. Өнөөдөр ДУУССАН ажлууд

### 2.1 Үржих тэмдэг цэгцэлсэн ✅
DB-д `\bullet` (бүдүүн хар цэг) хэрэглэгдэж байсныг бүгдийг `\cdot` болгов.

```
874 бодлого + 433 сонголт  →  \cdot
үлдсэн \bullet: 0   түүхий ∙: 0
нөөц: docs/100x100-v3/backup-bullet-20260826-1547.sql
```

### 2.2 GitHub-ийн задрал хаасан ✅
Репо **PUBLIC** байсан бөгөөд номын бодлогууд `.gitignore`-д ороогүй байв.
`git add -A` хийвэл 1,889 бодлого ил гарах гэж байсан. Мөн агентын үлдээсэн
`api/text.txt` (номын бүтэн текст, 366k тэмдэгт) хамгаалалтгүй хэвтэж байсан.

Хийсэн: `.gitignore`-т `docs/100x100-v3/`, `docs/research/`, `*.jsonl`,
`prisma/backup-*.sql`, `api/text.txt` нэмсэн; `api/text.txt` устгасан.
Git түүхэнд урьд нь орж байгаагүй нь батлагдсан.

### 2.3 Зөв бичгийн шалгагч суулгасан ✅
`dict-mn` (Hunspell, ~620k үндэс) толь дээр суурилсан шалгагч.

```bash
node prisma/spellcheck-mn.cjs docs/100x100-v3/import-ready.jsonl
node prisma/spellcheck-mn.cjs --json <файл>     # бүтэцтэй гаралт
echo "тэгшитгэлийг бод" | node prisma/spellcheck-mn.cjs -
```

Хоёр чухал шинж:
- **`$...$` доторх математикийг алгасна** — `MathText.tsx`-ийн ижил дүрмээр.
  Эс тэгвэл `\frac`, `\log` бүр алдаа болж хуурамч дохио үүснэ.
- **Цагаан жагсаалттай** (`prisma/dict-mn-allow.txt`, одоогоор 47 үг) —
  хүний нэр (Бат, Дорж, Цэрэн…), нэр томьёо. Таны хэлсэнчлэн толь хүний нэрийг
  мэдэхгүй; шошиглоод байвал багш дохиог сонсохоо болино.

**Батлагдсан үр дүн:**

| Эх сурвалж | Ялгаатай үг | Толинд байхгүй |
|---|---:|---:|
| DB-ийн одоогийн 100x100 (хүн шалгасан) | 364 | **19** |
| PDF-ээс задалсан шинэ хэвлэл | 396 | **139** |

DB-ийн 19-өөс бодит алдаа: «тэгшитгэлииг»→«тэгшитгэлийг», «шийдүүдйн»→
«шийдүүдийн», «Тодорхойдогдох»→«Тодорхойлогдох». Өөрөөр хэлбэл **прод дата
дээр ч жинхэнэ алдаа олж байна**.

### 2.4 Судалгааны баримт ✅

## 3. Шинэ хэвлэл яагаад ОРООГҮЙ вэ

PDF-ээс зургаар задлах арга **математикт зохистой, монгол бичвэрт найдваргүй**.
Дөрвөн шат дамжуулсан ч (13 агент → 12 агент 3-уншилт → 12 агент QA →
8 агент дахин уншилт) алдаа арилаагүй; дахин уншилт өөрөө шинэ алдаа оруулсан.

Эх номтой тулгаж баталсан:

| Задлалт | Ном |
|---|---|
| `\overline{7541237}` | `\overline{754123y}` ← **математик буруу** |
| «уржвэрийг» | «үржвэрийг» |
| «хуваагчын» | «хуваагчийн» |
| «тооүүдын» | «тоонуудын» |
| «тооғ» | «тоог» (`ғ` монгол үсэг ч биш) |
| «уттагал» | «утгыг» |

Нэг удаа 974 бодлого оруулаад **устгасан** — мэдэгдэж байгаа эвдэрсэн текстийг
продакшнд үлдээхгүйн тулд. Хуучин ном бүх хугацаанд хөндөгдөөгүй.

**Шийдэл: Word (.docx) файл.** `.docx` бол ZIP доторх XML — үсэг нь үсгээрээ
хадгалагдсан тул OCR огт байхгүй. Word-ийн тэгшитгэлийн обьектыг (OMML)
`pandoc -t latex` детерминистик хөрвүүлнэ. `pandoc 3.8` суусан байгаа.

### 🟠 B — Зөв бичгийн шалгагчийг UI-д холбох

| # | Ажил | Хүндрэл |
|---|---|---|
| B1 | NestJS `spellcheck` модуль үүсгэх | Дунд |
| B2 | `POST /spellcheck` — үгсийн жагсаалт авч, танихгүйг буцаана | Бага |
| B3 | Render дээр `hunspell` + толь байлгах | **Тодруулах** — доор үз |
| B4 | `ProblemClassifyEditor`-т улаан долгион зураас | Дунд |
| B5 | Багш «зөв үг» гэж нэмэх товч → цагаан жагсаалт өснө | Бага |

**B3-ын асуудал:** толь 18.4 MB, `hunspell` нь C++ бинар. Render-ийн Node
орчинд `apt install` хийх боломжгүй. Гурван зам:
1. Docker образ ашиглах (render.yaml өөрчилнө)
2. `nodehun` npm (native binding) — build хийгддэг эсэхийг турших
3. Толийг build үед татаж, `hunspell` бинарыг мөн татах

`nspell` (цэвэр JS) **туршаад бүтэлгүйтсэн** — 18MB толийг 5 минутад ачаалж
чадсангүй. Үүнийг дахин турших шаардлагагүй.
