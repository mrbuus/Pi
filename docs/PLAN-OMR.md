# OMR шалгалт — төлөвлөгөө (2026-11-12, эзний хүсэлт)

Төлөв (2026-11-12): **1–3-р шат ХИЙГДСЭН** (суурь, Excel импорт, багшийн хүснэгт, тойм, сурагчийн дэлгэц) +
бодлого бүрт **сэдэв ба томьёо** (эзний нэмэлт хүсэлт). Одоогийн бодит байдал — `STATUS.md` §7.29; доорх нь анхны
төлөвлөгөө бөгөөд зөрвөл STATUS давамгайлна. Үлдсэн: 4 (машины `.xls`/`key.ini`), 5 (2 дахь харагдацын жишээ), 6 (сантай холбох).
Өмнөх холбоотой баримт: `docs/v2/SHALGALT-TOLOVLOGOO.md` (6-р шат «OMR» — машины жишээ файл хүлээж байсан).

## 1. Зорилго

Төв ~600 сурагчийн цаасан шалгалтын хариултын хуудсыг OMR машинаар уншуулдаг.
Машины апп зөвхөн Windows, гаралт нь эмх замбараагүй. Хүсэж буй зүйл:

1. Машины гаралтын файлыг хүн гараар цэгцлэхгүйгээр вэб рүү шууд оруулах.
2. Багш бүх сурагчийн дүнг багаар, бодлого бүрээр, агуулгаар харах (2 харагдац).
3. Сурагч «Шалгалт» хэсэгт төвийн жагсаалтыг зөвхөн нийт оноогоор, өөрийн алдааг зөвхөн өөрөө харах.

Runtime-д AI дуудахгүй. Прод өгөгдөл устгахгүй, бүх «устгах» зөөлөн.

## 2. Одоо репод байгаа зүйл (дахин бичихгүй)

| Байгаа | Хаана | OMR-д хэрхэн ашиглах |
|---|---|---|
| Бодлого бүрийн зөв/буруу хүснэгт, эх `OMR` | `TestItemMark`, `ItemMarkSource.OMR` | Тест нь сантай холбогдсон үед энд бичнэ |
| Нийт дүн, эх `OMR_IMPORT` | `TestResult`, `AttemptSource.OMR_IMPORT` | Мөн адил; эрэмбэ (`ranking.service.ts`) аль хэдийн тоолдог |
| Excel-ээс «урьдчилан харах → батлах» урсгал | `exams/gradebook.service.ts` (`previewExcel`, `buildPreview`), `ExcelImportDialog.tsx` | Импортын UI, түгжээ, аудитын хэв маягийг дагана |
| Анализ (зөв %, ялгах чадвар, сэдвийн эзэмшил) | `exams/exam-analytics.ts` | Цэвэр функцүүдийг дахин ашиглана |
| Багшийн ангийн эрх | `exams/exam-access.ts` (Багш = өөрийн анги, Багш+/Админ = бүгд) | Яг энэ дүрмээр |
| Сурагчийн «Шалгалт» | `/app/tests`, `StudentExamsHub.tsx`, `/exam-results/my` | Шинэ хэсэг «Цаасан шалгалт» нэмнэ |
| БҮТ-ийн агуулгын муж | `Topic` (админ засдаг жагсаалт) | Бодлого → агуулга оноолтод ашиглана |

Анхаарах зөрүү:

- **Сурагчийн код.** Проданд 7 оронтой (`2027001`…) код хадгалагдсан (STATUS §9.1), `B27120001` формат руу шилжүүлээгүй. Импорт хоёуланг нь танина.
- **Цаасан шалгалтын бодлого санд байхгүй.** Одоогийн `Test` нь `TestProblem → Problem` шаарддаг. 48 бодлоготой төвийн шалгалтыг санд оруулаагүй байхад дүнг авах хэрэгтэй — доорх §3.

## 3. Өгөгдлийн загвар

Шийдэл: цаасан шалгалтад **хөнгөн тусдаа загвар** (бодлогын агуулга шаардахгүй), сантай холбох нь сонголттой.
Шалтгаан: (а) бодлого санд байхгүй ч дүн гарах ёстой; (б) түлхүүр зассан үед дахин дүгнэхийн тулд сурагчийн
**түүхий хариу (A–E)** хадгалах хэрэгтэй — `TestItemMark` зөвхөн зөв/буруу хадгалдаг; (в) танигдаагүй хуудас хүлээх газар хэрэгтэй.

```
PaperExam            шалгалт
  id, title, heldOn (огноо), itemCount, choiceCount (4|5)
  variants Json?     // хувилбар A/B… байвал: хувилбар бүрийн бодлогын дарааллын зураглал
  published Boolean  // сурагчид харагдах эсэх
  testId String?     // сангийн Test-тэй холбосон бол (сонголттой)
  createdById, createdAt, updatedAt, deletedAt

PaperExamItem        бодлого (1..N)
  examId, number, variant ("" эсвэл "A")
  answerKey String?  // "C"; хүчингүй болгосон бодлого = null (maxScore-оос хасагдана)
  points Int @default(1)
  topicId String?    // БҮТ-ийн агуулгын муж (Topic)
  @@unique([examId, variant, number])

PaperExamSheet       нэг сурагчийн нэг хуудас
  id, examId, importId
  rawCode String     // хуудсан дээр будсан шифр, машинаас ирснээр
  variant String
  studentId String?  // танигдаагүй бол null — багш гараар холбоно
  classroomId String? // импортын үеийн баг (хожим анги сольсон ч түүх хэвээр)
  answers Json       // ["C","", "A","*", …]  ""=хоосон, "*"=давхар будсан
  totalScore Float, maxScore Float   // түлхүүрээс бодсон кэш
  supersededAt DateTime?             // дахин уншуулсан бол хуучин нь
  @@unique([examId, studentId]) (supersededAt null үед — partial index)

PaperExamImport      нэг файл оруулалт
  id, examId, fileName, fileSha256, rowCount, matchedCount
  status PREVIEW|CONFIRMED|REVERTED, createdById, createdAt
```

- Зөв/буруу, оноо, агуулгын % — бүгд `answers` + түлхүүрээс **тооцоолно** (цэвэр функц, тесттэй). Түлхүүр засвал `totalScore` дахин бодогдоно, `AuditLog`-д бичнэ.
- Давхар будсан (`*`) ба хоосон = буруу; дэлгэцэнд ялгаж харуулна.
- `PaperExam.testId` тавьсан үед батлахдаа `TestItemMark` (OMR) + `TestResult` (OMR_IMPORT)-д давхар бичнэ → одоо байгаа анализ, эцэг эхийн «Танилцлаа» карт шууд ажиллана. Энэ нь 4-р шат, заавал биш.
- Агуулгын жагсаалт: Магадлал статистик, Геометр ба тригонометр, Анализын эхлэл, Алгебр, Тоо тоолол. `Topic`-т байгаа нэртэй тулгаж, дутууг эзэнтэй тохирч нэмнэ (нэр өөрчлөхгүй — одоогийн бүлгүүдэд холбоотой).
- Миграц нь зөвхөн шинэ хүснэгт нэмнэ (одоо байгаа хүснэгт хөндөхгүй). STATUS §4 «Миграцийн аюулгүй байдал»-ыг дагана.

## 4. Импорт

### 4.1 Машины файл

Өмнөх тэмдэглэлээр машины экспорт нь `Scored_Data.xls` + `key.ini`. **Жишээ файл гартаа ирээгүй** тул формат баталгаагүй — §9-ийн асуулт.
Файл ирмэгц хийх зүйл: бүтцийг судалж цэвэр parser (`paper-exams/omr-parse.ts`, I/O-гүй, жинхэнэ файлаас авсан fixture-тэй тест) бичнэ.
Аппыг задлах шаардлагагүй гэж үзэж байна: экспортын файл л хангалттай. Хэрэв экспорт нь уншигдахгүй хоёртын формат бол тэр үед аппын өгөгдлийн санг (ихэвчлэн `.mdb`/`.db`/`.ini`) уншина.

Windows дээр нэмэлт программ суулгахгүй: ажилтан машины аппаас «Экспорт» дараад файлыг вэбийн хуудас руу чирнэ. Parser серверт ажиллана.

### 4.2 Урсгал (Excel импортын хэв маягаар)

1. Багш+/Админ шалгалт үүсгэнэ: нэр, огноо, бодлогын тоо, түлхүүр (гараар эсвэл `key.ini`-ээс).
2. Файл чирнэ → **урьдчилан харах**: хэдэн хуудас, хэд нь сурагчтай таарсан, танигдаагүй шифр, давхардсан шифр, давхар будсан нүдний тоо, бодлогын тоо зөрсөн эсэх.
3. Танигдаагүй мөрийг гараар холбоно (сурагч хайх) эсвэл алгасна.
4. **Батлах** → хадгална. Ижил файлыг (sha256) дахин оруулбал анхааруулна. Сурагчийн өмнөх хуудас байвал солих эсэхийг асууна (хуучин нь `supersededAt`, устахгүй).
5. Импортыг бүхэлд нь **буцаах** боломжтой (`REVERTED`, зөөлөн).

Шифр ↔ сурагч: эхлээд `User.studentCode` яг таарах → `StudentCodeLegacy.oldCode` → таарахгүй бол гараар. Дүрэм §9-ийн хариултаас хамаарна.

### 4.3 Нөөц зам

Машины файл ирэхээс өмнө ч ашиглаж болохоор: эзний одоогийн хүснэгтийн хэлбэрийг (№, Шифр, Овог, Нэр, Оноо, Сул агуулга, 1..N; зөв = 1) шууд уншдаг Excel импорт. `gradebook-sheet.ts`-ийн туслах функцүүдийг дахин ашиглана. Энэ замд түүхий хариу байхгүй → зөв/буруугаар хадгална (`answers`-д `"+"`/`"-"`).

## 5. Багшийн дэлгэц

Байршил: «Шалгалт» → шинэ таб «Цаасан шалгалт» (`/app/tests`), дэлгэрэхэд Дүн | Агуулга | Түлхүүр | Импорт.

**Харагдац 1 — Багийн хүснэгт** (жишээ файлын дагуу):

```
Баг 27, Багш: Болор-Эрдэнэ, 15 сурагч                      [Excel татах]
 №  Шифр     Овог  Нэр   Оноо  Сул агуулга          1 2 3 … 48
 1  2027014  …     …     37    Магадлал статистик   1 1 . … 1
 …
    Гүйцэтгэл %                                     93 80 40 … 67
 АГУУЛГЫН ТӨРЛӨӨР, ГҮЙЦЭТГЭЛ %
 Магадлал статистик 44   Геометр ба тригонометр 55   Анализын эхлэл 62   Алгебр 71
```

- «Сул агуулга» = тухайн сурагчийн хамгийн бага хувьтай агуулга (тэнцвэл хоёуланг).
- Бодлогын баганын өнгө: ногоон 70-аас дээш, шар 40–70, улаан 40-өөс доош (одоогийн анализын дүрэм).
- Нүд дээр дарвал сурагчийн сонгосон хариу, зөв хариу.
- Excel татахад эзний одоогийн хуудастай ижил хэлбэр, баг бүр нэг шийт.
- Утсан дээр: сурагчийн карт (оноо, сул агуулга), дарахад бодлогын мөр — 48 багана утсанд багтахгүй.

**Харагдац 2** — эзэн жишээ өгнө (§9). Түр таамаг: «Тойм» — бүх багийн харьцуулалт (баг бүрийн дундаж, агуулга × баг дулааны зураг, онооны тархалт, хамгийн их алдсан 10 бодлого). Жишээ ирэхэд тааруулна.

**Түлхүүр таб** (Багш+/Админ): бодлого бүрт зөв хариу, оноо, агуулга. Агуулгыг бөөнөөр оноох (1–12-г сонгоод «Алгебр»). Бодлого хүчингүй болгох.

## 6. Сурагчийн дэлгэц

«Шалгалт» (`/app/tests`) → «Цаасан шалгалт» хэсэг, шалгалт бүр карт.

- **Жагсаалт:** тухайн шалгалтыг өгсөн төвийн бүх сурагч — байр, нэр, баг, нийт оноо. Өөрийн мөр тодорсон. Бодлогын задаргаа, агуулгын хувь БАЙХГҮЙ.
- **Миний дүн:** оноо, байр, агуулга бүрийн хувь, бодлого бүр (зөв/буруу, өөрийн сонгосон хариу, зөв хариу), алдсан бодлогын жагсаалт агуулгаар бүлэглэсэн.
- Шалгалтыг сантай холбосон бол (`testId`) алдсан бодлого дээр бодлогын өгүүлбэр, бодолт, «Ижил сэдвийн бодлого бодох» (`/study-review`). Холбоогүй бол зөвхөн дугаар ба агуулга — «бодлогын агуулгыг ойлгуулах» нь энэ холбоосоос шалтгаална.
- Эцэг эх: хүүхдийн оноо, сул агуулга (одоогийн картын хэв маяг).

## 9. Эзнээс тодруулах

1. **Машин ба апп:** машины загвар, аппын нэр, хувилбар. Экспортын сонголтууд (xls, csv, txt) юу байдаг вэ?
2. **Жишээ файл:** нэг бодит шалгалтын экспорт (`Scored_Data.xls`, `key.ini` болон тухайн хавтсанд үүссэн бусад файл бүгд) + тэр шалгалтын зөв түлхүүр. «Эмх замбараагүй» гэдэг нь яг юу вэ (багана холилдсон, нэр байхгүй, кодчилол эвдэрсэн)?
3. **Шифр:** хуудсан дээр сурагч юу буддаг вэ — 7 оронтой сурагчийн код (`2027001`) уу, тусдаа шифр үү? Хэдэн оронтой? Тусдаа бол шифр ↔ сурагчийн жагсаалт хаана байдаг вэ?
4. **Баг:** «Баг 27» нь вэб дээрх анги (`Classroom`) мөн үү, эсвэл шалгалтад зориулсан тусдаа хуваарилалт уу?
5. **Хувилбар:** шалгалт A/B хувилбартай юу? Хуудсан дээр хувилбар буддаг уу?
6. **Оноо:** бодлого бүр 1 оноо юу, жинтэй юу? 2-р хэсэг (нөхөх) OMR хуудсанд байдаг уу?
7. **Харагдац 2**-ын жишээ.
8. **Нэр ил харуулах:** сурагчид бие биеийн нэр + нийт оноог харах нь зөв үү (одоогийн дүрэм нэрийг нуудаг)? Эцэг эх жагсаалтыг харах уу?
9. **Багш:** энгийн Багш бусад багийн дүн, бүх багийн тоймыг харах уу?
10. **Агуулга:** 5 ангилал яг энэ үү (Магадлал статистик, Геометр ба тригонометр, Анализын эхлэл, Алгебр, Тоо тоолол)? Нэг бодлого нэг л агуулгатай юу?
11. **Сантай холбох:** шалгалтын бодлогууд санд (ном, 1000 бодлого) байдаг уу, эсвэл тухай бүр шинээр зохиодог уу? Шинэ бол PDF-ийг оруулж сурагчид алдсан бодлогоо харуулах уу?
