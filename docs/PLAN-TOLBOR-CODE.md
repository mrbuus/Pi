## В. Эцэг эх

**В1. Баталгаажуулалт (дүнтэй танилцлаа):** цаасан гарын үсгийг орлоно.

Судалсан 3 хувилбар:
1. **SMS OTP** — танилцлаа дарахад бүртгэлтэй утас руу код очно. Хямд, одоо хийж болно, (цаг + утас + код + IP) хадгалснаар цаасан гарын үсгээс дутахгүй мөрдлөг үүснэ. **← Санал болгож байна**
2. ДАН (үндэсний eID) — хамгийн албан ёсны, гэхдээ гэрээ/интеграц удаан. Хожим нэмж болно.
3. Зурган гарын үсэг — баталгаа сул, зөвлөхгүй.

| # | Таск | Файл |
|---|------|------|
| В1а | `ResultAcknowledgement` модель: testResultId, parentUserId, otpVerifiedAt, ip | schema |
| В1б | Дүн гарахад эцэг эхэд мэдэгдэл → үзээд «Танилцлаа» → OTP → бичлэг | parent module |
| В1в | Багшийн самбарт: шалгалт бүрээр танилцсан / танилцаагүй жагсаалт | web |
| В1г | Эцэг эх холбох зөвхөн ТАНХИМЫН сурагчид (онлайнд хаана) | parent.service |

**В2. Төлбөрийн сануулга:**

Дуусах огнооны дүрэм (гэрээний дагуу): сүүлийн баталгаажсан төлбөрөөс эхлэн
**хичээлийн өдрөөр** тоолно. Зөвхөн **нийтээр амарсан өдөр** тооцогдохгүй;
чөлөө, таслалт **тооцогдоно** (төлбөрт орно). Хуанли (`AcademicCalendarDay`) +
`expandDays()` аль хэдийн байгаа — шинэ тооцоо биш, шинэ хэрэглээ.

| # | Таск | Файл | Тест |
|---|------|------|------|
| В2а | `paidUntil` цэвэр функц: төлбөрийн огноо + төлсөн хугацаа → дуусах огноо | `tuition/paid-until.ts` | 10+ кейс |
| В2б | Эцэг эх/сурагчийн самбарын дээд хэсэгт banner: «Сургалтын төлбөрийн хугацаа 2026-09-12-нд дуусна. Хугацаанаас өмнө төлбөрөө шийдвэрлэнэ үү.» (бүтэн төлсөн хүүхдэд харагдахгүй) | web |
| В2в | SMS сануулга: дуусахаас N хоногийн өмнө (default 3, тохируулгатай) | notifications |

## Г. Сурагчийн код (шинэ формат)

**Формат:** `[Үсэг][ЖЖ][АА][ДДДД]` — жишээ `B27120001`

| Хэсэг | Утга |
|-------|------|
| Үсэг | B = Баруун4, Z = Зүүн4, O = Онлайн, A = Багш |
| ЖЖ | Бүртгүүлсэн он (сүүлийн 2 орон, УБ цагаар) |
| АА | Анги (11, 12…). Багшид үргэлж 12 |
| ДДДД | Төвд бүртгүүлсэн глобал дараалал (0001, 0002…) |

Дараалал 9999 хүрвэл АА-г 13 болгож үргэлжлүүлнэ (таны заасан дүрэм;
жилд ~500 бүртгэлтэй тул бодитоор хүрэхгүй).

**Код үүсэх 3 зам:**
1. Багш гараар бүртгэнэ → код ШУУД үүснэ
2. Онлайнаар танхимын ангид бүртгүүлнэ → багш зөвшөөрнө **+ суудал баталгаажуулалт** (эхний сарын төлбөр CONFIRMED) → код үүсч, мэдэгдэл очно
3. Дан онлайн худалдан авагч → зөвшөөрөл хэрэггүй, гэхдээ **төлбөр CONFIRMED болмогц л** код үүснэ

Нэвтрэлт одоогоор утсаараа хэвээр — кодоор нэвтрэх бол дараагийн үе шат.

| # | Таск | Файл | Тест |
|---|------|------|------|
| Г1 | Шинэ генератор (хуучин SIE-г солино): салбар/төрөл → үсэг, глобал дараалал, зэрэгцээ давхцлын хамгаалалт | `common/codes.ts` | 12+ кейс |
| Г2 | Үүсэх 3 замын дүрэм: pending бүртгэл → зөвшөөрөл + төлбөр шалгаад код олгох төлөвийн машин | auth + enrollment | unit |
| Г3 | Танхимын онлайн бүртгэлийн «зөвшөөрөл хүлээж буй» жагсаалт + зөвшөөрөх UI (багш) | web | — |
| Г4 | 359 сурагчийн backfill migration: createdAt дарааллаар шинэ код олгоно | migration | dry-run |
| Г5 | Код харагдах бүх газрыг шинэ форматад (profile, жагсаалт, хайлт) | web | — |

**Эзний шийдвэр Г:** Хуучин SIE-кодыг бүрмөсөн СОЛИХ уу (санал: солих, нэг л
код байг), эсвэл хуучныг түр зэрэгцүүлэн хадгалах уу?
