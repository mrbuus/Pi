# Feedback and bug reporting

New authenticated `/app/feedback` workspace and `/api/feedback` routes are implemented in the v2 checkout. All six existing roles can send BUG, SUGGESTION or QUESTION tickets and read their own history/details. ADMIN can list all tickets and set OPEN, IN_REVIEW or RESOLVED with an author-visible reply. Other roles cannot read another user's ticket or triage, enforced server-side independently of the UI. No email/SMS is sent.

Create requests carry a per-user UUID `clientRequestId`. Identical retries return the original record; concurrent unique-key collisions read the winning record. Reusing a request ID for different content returns a conflict. Subject/body limits and trimmed text are validated, as are attachment count and internal context paths. Absolute URLs, protocol-relative URLs, traversal, query strings and hashes are rejected, keeping tokens and URL secrets out of automatic context links. Ticket detail text is escaped by React rather than interpreted as HTML.

Optional screenshots are restricted to three new author-owned StoredFile keys with approved raster image MIME. Legacy ownerless files, foreign keys and PDFs are rejected. Uploads record the authenticated uploader ID, with an updated existing upload regression test. The form asks users to omit codes, passwords, bank information and others' private information; no automatic screenshot capture or financial attachment selection occurs. Successful uploaded keys are cached within the open form, so a failed ticket submission does not reupload earlier files. Failed drafts, file selection and admin responses remain visible and retryable. This is an in-memory draft, not a claim of offline persistence after closing the page.

History fetches are bounded to 50 visible records plus one pagination sentinel. Scope/request changes ignore superseded list responses. Clicking a record loads server-authorized details and focuses the detail panel for keyboard and mobile users. Empty/loading/error/retry and reply-pending states are explicit.

Validation completed: feedback service/DTO 24 tests and controller HTTP 14 tests with real role guards/validation, thirteen theory retry/ownership tests, fourteen submission history/ownership tests, and nine upload tests including actual Express HTTP serving. API and web TypeScript pass. The earlier production web build passed; the final upgraded integrated build is coordinated by root. Modified feedback/theory editor/dialog files lint without errors; the existing theory parent loader has three synchronous-effect warnings.

Live isolated API checks pass for all six roles creating and replaying their own tickets, forbidden foreign details, admin-visible replies, rejected foreign screenshots, private file cache headers and file ownership, theory concurrent deduplication and changed-payload rejection, teacher return preserving the original pupil answer, resubmission revisions, and verified parent history. New foreign submission/teacher assignment/theory attachment keys return 403, and verified parents cannot acquire access through rejected keys. No production accounts or finance data were used.

Headless mobile checks pass for six-role login/public-home return, student study back navigation, screenshot feedback, and the theory dialog’s cancel focus, Tab trap, Escape retention and opener focus. A simulated failed feedback POST preserves the draft and same UUID and reuses its already uploaded screenshot. A real theory INSERT followed by a simulated lost acknowledgment preserves the draft; retry uses the same UUID and results in one saved block. Reviewed DOCX import and duplicate detection pass at 375px without overflow after the document-import owner’s button/label fix. Online review/resubmission UI remains a separate pending fixture check.

## Theory author upload audit

Theory authoring now treats a selected image/alt as an unsaved draft, preserves failed files for retry, checks existing allowed image types/25MB limit, prevents duplicate click writes, blocks save until selected image is uploaded or removed, disables cancellation while uploading/saving and supports the shared preview. Alt brackets/newlines are normalized so image markdown remains parseable. Existing text remains after a failed save.

The theory discard/delete ConfirmDialog now uses the installed Radix Dialog primitive, focuses cancel first, traps focus, cancels safely on Escape, and restores the opener focus. Outside clicks do not discard edits. TypeScript, scoped ESLint, and live headless keyboard regression passed.

Theory creation now supports an actor-scoped UUID retry key. The editor keeps the same key for an unchanged draft after an uncertain network response; the server returns the existing block for exact payload replays, rejects changed-payload key reuse, and recovers the database uniqueness race. New draft remounts and changed payloads create fresh keys. Thirteen regressions cover replay, mismatch, actor scope, concurrency, JWT actor use, UUID validation, and new image ownership. Legacy clients without a request key remain compatible but cannot claim retry deduplication. Both disk and database file-serving paths now use private,no-store and no-referrer headers, with sendFile caching explicitly disabled; nine upload regressions pass, including actual HTTP serving from a hidden upload folder, database recovery, and a disk disappearance race.

High-risk remaining items: Owner-controlled screenshot descriptions cannot automatically redact image pixels; manual redaction remains necessary. The exact prior feedback-response edit history is not retained by the root-requested single-response schema.
