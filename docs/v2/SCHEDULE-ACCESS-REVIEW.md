# Local schedule access review

Schedule edits require `schedule.manage` for the affected classroom. Moving an entry checks original and destination scopes before writing. Bulk, recurring split, cancel/move exceptions and exception removal follow the same contract. Global teacher workday edits, teacher options and workday roster reads require a global schedule grant. Teacher and Teacher+ may retain their own explicitly assigned lesson topic (fallback: classroom owner when no lesson teacher); a random Teacher+ requires a grant. Calendar holiday mutation remains administrator-only.

Class timetable reads filter active classrooms to current pupil enrollment, verified parent's current enrolled child, own/assigned teacher classes, or granted management scope. BUYER and pending parents receive an empty general timetable and cannot guess another class or schedule ID. A class-scoped manager reads that class, without a global staff roster. The week query filters schedules and exceptions before resolving; non-global viewers do not query global teacher workdays, exceptions or roster. School calendar holiday information remains readable to authenticated users. Existing personal ICS already filters own classes and archived classrooms and remains unchanged.

All-teacher schedule-derived hours require global `time.review`. Teachers can still read their own derived hours. The hours UI resolves the actual time.review grant before choosing the all-teacher route, so an ungranted Teacher+ receives their own hours, and labels totals as schedule estimates. Schedule permission is not time-review permission and these totals are not a claim of actual logged work, approved timesheets or payroll entitlement. The root's shared service validates current database role, active user, persisted capability, global/classroom scope, expiry and revocation; a JWT role claim alone grants nothing.
