# Persistent class-day learning flow

Teacher `/app/lesson-flow` opens actual class/day/chapter, reads existing theory images/PDF links, records a class test, chooses a published A makeup variant, edits an automatically filled homework suggestion and saves one durable packet. PUT `/lesson-flow/classrooms/:id/day?date=YYYY-MM-DD` locks the class in a PostgreSQL transaction, validates chapter/theory/test ownership references, creates or reuses ClassTestSession and Assignment, then upserts the class/date packet. Replays do not duplicate work. Later teacher edits preserve assignment/session IDs; missing explicit theory selections retain earlier manual additions/removals. Packet chapter identity is frozen after first save. Ordinary test exclusions survive reuse.

Only administrator or classroom-owning teacher/teacher-plus can save, preview, assign/override a photo turn, or read another pupil's receipt. A plus role alone grants no random class access. GET `/lesson-flow/days/:id?studentId=` lets owner staff inspect a historical enrolled pupil, and verified parents inspect only their own historical enrolled child. Pupil membership uses the UB calendar day, including join day and excluding leave day. Archived class packets remain readable by historical pupils/verified parents/owner staff; new teacher mutations require an active class.

Pupil `/app/lesson-flow/my` reads saved day theory and classmates' shared theory photos, follows the actual makeup A test and existing homework/study flows, and uploads its own THEORY/CLASS_TEST/HOMEWORK/MAKEUP evidence through the existing upload helper. Receipts allow10 trusted author-owned image/PDF keys, each at most10MiB. Append-only unique `(packetId,studentId,kind,clientRequestId)` preserves previous snapshots. Exact replay returns the same row; altered attachment payload with that request ID returns409. A pending browser receipt stores its keys/request ID in sessionStorage, so reopening the day/type can retry without another logical receipt. Receipt upload is submission evidence, never a correctness or attention grade.

Class-size denominator is distinct enrollment-day pupils. Theory count is distinct THEORY receipt authors. Class test count unions distinct CLASS_TEST receipt authors, pupils whose included bank problems all have a real nonnull evening state for that class/day, and fully submitted online test sessions started on that class day. Partial marking does not count, and FAILED/GUESSED completion does not mean success. Homework count unions packet HOMEWORK receipts with submittedAt evidence on the actual packet-linked Assignment. No-row packet theory is unknown; an existing packet with no receipts has an actual zero.

POST `/lesson-flow/days/:id/photo-turn` serializes with class saves. It selects present/late pupils only, records one stable turn, tracks pending/served cycle and prioritizes absent unserved pupils when they return. Repeated automatic requests return the same turn. Teacher override requires an eligible pupil and visible reason; it keeps the turn ID and requeues an unserved replaced pupil. A selected turn and uploaded photo are distinct records; the system does not claim a photograph was supplied merely because an assignment was made.

File authorization checks receipt references: THEORY is shared with historical-day classmates and verified parents; CLASS_TEST/HOMEWORK/MAKEUP is private to author, verified parent, assigned teacher or admin. Private-reference precedence prevents copying a private key into THEORY from broadening access. Root-owned upload headers and current database token lifecycle checks remain in force. Ownerless theory files also receive a real saved packet-theory/member reference grant. Parent annual history includes authorized packet IDs/day/title and that child's receipt keys/time, without internal notes, actor details or other children's private receipts.
