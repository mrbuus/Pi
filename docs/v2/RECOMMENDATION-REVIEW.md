# Recommendation contract — local v2

The recommendation contract is `observed-independent-v1`. STUDENT and BUYER receive only currently entitled chapter candidates. Cold-start selection is deterministic by chapter order/id; current classroom progression bounds fresh chapters in the same book while retaining historically encountered topics. Candidates are real bank problems and contain no answer keys. Requests are bounded to 1–50 results, source evidence to 10,000 rows per source and eligible candidate chapters to 12; this is bounded scheduling, not a complete lifetime estimate.

Only first measured, unassisted, graded responses contribute to the independent estimate. Corrections, guessed/helped responses, classroom self-reports, null grades and repeated responses have separate counts. A later hint does not erase an earlier independent result. Unknown correctness is not failure. Existing bank correctRate is an aggregate difficulty heuristic; zero remains zero and missing values use a neutral default. Mixed historical aggregate difficulty is not a measured individual ability.

Returned evidence counts and explanations are visible progressively in Study. Fewer than five independent observations are explicitly a small sample; larger counts remain observations, not calibrated probability. The scheduler's legacy `mastery` value is a smoothed binary fraction and its score orders candidates. Neither is BKT/IRT/DINA/Elo, a learning-style classification, an exam forecast or validated educational efficacy. Spacing and interleaving are deterministic next-task rules, with research context in LEARNING-REVIEW.md; learning gains need independent longitudinal evaluation.

Verification: 32 recommendation unit tests cover cold start, role/entitlement filtering, evidence exclusions, zero accuracy, bounds and scheduler behavior. Combined owned API suites passed 16 suites/92 tests. Synthetic local PostgreSQL plus real HTTP guards/controller integration verifies BUYER access after chapter pass, unauthorized paid chapter denial, no key fields, fresh candidates, malformed limits and rejection of spoofed correctness. No production data or external providers were used. API build and targeted API/UI lint passed; full browser Study interactions were not exercised by this subagent.
