# Per-problem video explanations — local v2

Video keeps its chapter link and may additionally reference one exact Problem ID. The FK prevents hard deletion of a referenced problem. Creator ID is recorded for new uploads/links; legacy ownerless entries are not claimable by an ordinary teacher. Teacher+ and Admin retain global curation and may attach/detach a problem only from the same chapter. An ordinary teacher can edit their own video's title/source/chapter but cannot change the problem mapping or delete videos. Create/update/soft-delete and their audit rows commit in one transaction; mapping changes and deletion serialize by video ID. Editing a chapter while retaining an incompatible problem mapping is rejected. There is no immutable problem-version pin: source-version history remains a separate requirement.

`GET /videos/problem?problemId=...` is registered before dynamic video routes and returns only entitled video ID/title/duration/chapter/problem metadata. `POST /videos/:id/open` rechecks entitlement and exact mapping before returning safe media. Pupil/BUYER opening an explanation records a server-time HINT_USED event, which recommendation evidence excludes from later independent success. This event means exposure requested, not successful playback, attention or completion. Regular learner chapter-video lists exclude mapped solution videos; chapter videos remain available. Soft-deleted videos remain stored with mapping and audits, and disappear from learner lists. No problem answer key is queried or returned.

Content administration can map an existing video to a copied full Problem ID or clear that field to detach it. The Library provides the full ID progressively. Library, Practice and Study (after first response for bank problems) show a lazy “Бичлэгээр тайлбар” disclosure: metadata loads only on click, one selected source loads after deliberate opening, and the pupil returns to the same problem without navigation. The shared chapter/lesson player also waits for a click. Direct HTML video uses `preload=none`; YouTube disables autoplay and is reconstructed from a validated 11-character ID. Frame height stays at least 200px. No arbitrary iframe URLs, hostname-substring matches or HTTP media are supported.

Active BOOK purchases grant theory and problems regardless of includesVideo; media purchases require includesVideo. Both enforce grantedAt at or before now and expiry strictly after now; refunds/revocations clear grantedAt (payments reversal does this). Passes require startsAt at or before now, active definition and unexpired grant. Pass-only scope remains separate from content-purchase scope so a plain book cannot accidentally unlock media. Content listing and direct access are tested to agree.

The API accepts canonical HTTPS YouTube watch/short/embed URLs and exact origins listed in `TRUSTED_VIDEO_ORIGINS` for MP4/WebM. The browser independently uses `NEXT_PUBLIC_TRUSTED_VIDEO_ORIGINS`; configure both consistently. Defaults are empty, so direct-media provider absence is explicit, while YouTube links work without a direct provider. No direct file uploader, signed streaming provider, live URL existence check, redirect inspection or DRM was fabricated. Trusted origins must themselves serve trusted media without unsafe redirects. Previously stored unsafe links remain teacher-reviewable but are not executable in the shared player.

YouTube documents that autoplay enables playback and data sharing on page load; this implementation uses autoplay=0 and delays iframe mounting. Its documented minimum embedded viewport is 200×200. [Official player parameters](https://developers.google.com/youtube/player_parameters). Privacy-enhanced embedding uses youtube-nocookie.com and limits how embedded viewing influences the YouTube experience; it does not mean zero third-party communication after opening. YouTube requires appropriate site/app child-directed designation even with privacy-enhanced mode, which remains operator configuration. [Official embedding/privacy guidance](https://support.google.com/youtube/answer/171780).

Unlisted is discoverability control: anyone with the link may view and share it. Private YouTube sharing uses selected viewers and may not work as a general pupil embed. Pi.mn entitlement protects the application endpoint, not a copied provider link, and no DRM promise is made. [Official video privacy settings](https://support.google.com/youtube/answer/157177). YouTube iframe completion is not inferred from loading or clicking; without the player API's verified state callbacks, completion remains unknown. Direct-media start/end callbacks use actual HTML video events.
