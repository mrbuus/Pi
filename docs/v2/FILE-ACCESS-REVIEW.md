# Local v2 file access review

The file guard verifies HS256 expiry, reloads the current database user/role, rejects archived accounts and tokens issued before a password change, then authorizes the exact key. A login alone is no file grant. StoredFile.ownerId permits the author's unattached draft; administrator access remains. Ownerless legacy keys require a known authorized reference.

Submission and revision attachments permit the pupil author, verified linked parent, and teacher/teacher-plus owning the assigned classroom. Historical and archived assignment references remain valid. Private attachment references take precedence over copied content/cover/avatar references. Feedback attachments permit their author and administrator. Teacher-plus membership alone never grants random pupil photographs.

Theory/problem/video chapter references use existing canAccessChapter semantics, including active passes and granted book purchases with video entitlement. Verified parents use their child's chapter entitlement. Catalog covers, historical assignment enrollment windows, scoped pupil/teacher avatars, and entitled published test PDFs retain their respective reference grants. Unpublished tests require their staff author or administrator. There is no blanket ownerless-key fallback.

Verification: API build; 11 new file tests (plus existing storage/learning tests, 21 total in focused run); opt-in `node src/storage/files.local.integration.cjs` against approved localhost PostgreSQL port 5544 with actual production guard and authorization service over HTTP. Real fixtures cover pupil/other pupil, verified/unverified parent, assigned teacher/random teacher-plus/admin, archived assignments and revision attachments, draft ownership, ownerless unattached keys, expired/archive/password-revoked tokens, ignored forged token role, and no-store/no-referrer headers. Fixtures are removed. Unit coverage additionally covers free-preview content, copied-private-file precedence, and random pupil avatars. Purchased-book and avatar enrollment combinations use existing entitlement helpers and are not yet exhaustively exercised as real DB fixtures.

The existing native img/PDF fileUrl contract still transports the full bearer token in a URL query. Response no-store/no-referrer headers reduce caching and onward referrer exposure; they cannot prevent initial URL exposure through browser history, proxy/server logs, monitoring, or copied URLs. [RFC 6750 section 2.3](https://www.rfc-editor.org/rfc/rfc6750#section-2.3) discourages URI bearer tokens because URLs are likely logged. A future replacement should issue short-lived signed tickets scoped to one file key, user, expiry, and purpose through a bearer-authenticated endpoint, recheck account/object permission at consumption, and redact ticket query parameters from logging. It requires coordinated fileUrl/client/controller changes; this review does not claim tickets are implemented. Header behavior follows [MDN Referrer-Policy](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Referrer-Policy) and [MDN Cache-Control](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Cache-Control).

Learning evidence audit: correction and solution exposure now use the same per-user/problem PostgreSQL advisory transaction lock, so concurrent requests cannot record a post-exposure retry as pre-solution. Focus timing ignores invalid/backward timestamps, keeps its monotonic high-water mark, and classifies the next elapsed interval unknown; four clock tests cover regression without double counting. These are visible/focus observations, never proof of attention or speed-based ability labels. Existing local learning HTTP integration passes after serialization.
