# Self-selected topic review: exact next-step contract

Status: **tested locally with PostgreSQL/JWT/HTTP and365/375px browser acceptance**. `StudyReviewModule` and `/app/study/review` use persisted runs rather than modifying official TestAttempts. The proposal below records the rationale; the implementation evidence and exact limits are listed at the end.

The current `POST /tests/:id/start` takes no pupil duration/topic input. Its server deadline comes from teacher-owned `Test.timeLimitMin`. `TestAttemptSession` and `TestResult` are unique per test+pupil; reusing that identity for multiple pupil review runs would overwrite/collapse historical attempts or resume a finished exam. Learner `GET /tests` omits exact chapter ID/title, while `/lessons/:chapterId` only supplies associated test IDs and ordinary lesson chapter listing omits test-only topics. Inferring topics from titles/groupKey or changing a teacher's time limit would be incorrect. Pupil-created official Tests would also grant unwanted curation and pollute official rankings. A client-only timer cannot enforce a persisted deadline across reload/devices.

## Minimal additive persistence

Proposed `StudyReviewRun`: id; userId FK Restrict; clientRequestId; normalizedRequestHash; budgetMinutes (only 10/30/60); requestedChapterIds[] (1–5); status OPEN/SUBMITTED/EXPIRED; startedAt; deadlineAt; submittedAt?; selectionVersion; seed; createdAt; `@@unique([userId,clientRequestId])`; index(userId,startedAt). Unique request replay returns the same run; differing topic/budget payload conflicts. Deadline is computed by the server once and never reset by reload, heartbeat or edits.

Proposed `StudyReviewItem`: id; runId FK Restrict; problemId retained FK Restrict or versioned generated template ID; order; internal sourceSnapshot JSON; internal gradeSnapshot JSON; gradingVersion; eligibilityAtStart; exposureBeforeFirst boolean; firstRecordedAt?; immutableFirstAnswer?; immutableFirstFlags[]; immutableFirstCorrect boolean?; `@@unique([runId,order])` and `@@unique([runId,problemId])`. Internal snapshots freeze statement/image refs/choices and reviewed answer/grading rules for the run. API projections never return answer keys before submission. Current bank IDs are permanent but not content-version pins; this snapshot gate is required before shipping the feature.

Proposed append-only `StudyReviewResponse`: id; itemId FK Restrict; userId; clientRequestId; kind FIRST/CORRECTION; answer; flags[]; correct boolean?; occurredAt server time; assistance; `@@unique([itemId,userId,clientRequestId])`. The first response is captured transactionally once; correction never replaces it. Replayed client request must compare payload and conflict on changes. Existing LearningEvent remains the activity stream, with source REVIEW_RUN and run/item identity. New records must not insert official TestResults, update exam ranks, or masquerade as classroom assignments.

## Service/API contract

- `GET /study-review/options`: current STUDENT/BUYER only; exact entitled chapter IDs/titles and fresh eligible item counts, not keys. Entitlement uses current roles, active class/pass/purchase rules and source soft-delete status. Topic IDs are explicit, not inferred from titles.
- `POST /study-review/runs`: budget, 1–5 deduplicated chapter IDs and UUID request ID. Transaction locks per pupil/request, validates every chapter, freezes a bounded reviewed item selection and deadline. A first release can use fixed reviewed caps 5/10/20 items for 10/30/60 minutes (maximum 20); these are product limits, not empirically measured pace or ability. Exclude unsupported/manual grading from automatically scored independent items. Return a useful no-eligible-items result; never fabricate replacements.
- `GET /study-review/runs/:id`: ownership and current entitlement; returns frozen order, safe source projection, recorded first/corrections and server remaining time. Entitlement loss hides newly requested source material while preserving owned answer/history metadata and the original deadline; never erase records or silently restart. The operator must confirm this licensing behavior before release.
- `POST /runs/:id/items/:itemId/response`: ownership, item membership, OPEN/server deadline and bounded typed answer/flags; idempotent append. Grading comes from reviewed immutable key/version, never client `autoCorrect`. Expired response is rejected without overwriting the draft or first answer. Focus/hidden summaries remain client-observed bounded counters with unknown attention, unique chunk IDs and no speed-based ability label.
- `POST /runs/:id/submit`: lock run, persist final reviewed result and status once; repeated same request returns it. Explicitly distinguish fresh measured first responses, previously seen revisits, guessed/helped answers, corrections and unknown grades. A server-expired run closes with only actual recorded answers; unseen unanswered items are not invented learning failures.

Selection must include source provenance. Seen IDs across Attempt, lab-first and prior review items are excluded from the fresh pool. If a selected topic lacks enough new items, offer an explicitly labeled revisit with a separate evidence category rather than calling repeats unseen independent success. Video/text explanation requests before first response mark assistance; later exposure must not erase a prior independent first response. Delayed probes use new reviewed item identity and retain spacing rationale without claiming calibrated mastery/BKT/IRT.

## Durable annual history — 2026-10-07 implementation

`GET /study-review/history` is owned by the current STUDENT/BUYER. `GET /study-review/children/:childId/history` is PARENT-only and requires the exact verified ParentLink plus a current nonarchived STUDENT child. Missing/unverified/other-child links are 403. Both use one safe projection; no current book/pass entitlement is required for the historical summary. Reopening an owner run still applies the existing content gate, and parents do not receive full runs or source/key snapshots.

Optional `year` is a four-digit modern UB calendar year 2000–2100, defaulting to current Asia/Ulaanbaatar year. Jan 1 00:00 +08 inclusive through next Jan 1 exclusive bounds `startedAt`. `take` is 1–50 (default20). Pages sort startedAt then id descending. Opaque base64url cursor carries run id/year and is resolved again against the same owned/year-bounded database scope; malformed, foreign or wrong-year cursors return400. No arbitrary timestamp is trusted from cursor data.

Rows contain id, budgetMinutes, state, startedAt/deadlineAt/submittedAt and evidence counts: assigned, answered, firstCorrect, independentFirstCorrect, assistedFirst, correctedWithAssistance, unknown. An OPEN run past its deadline projects EXPIRED without rewriting first evidence or official results. Corrections never replace original score; assisted correction count is separate. Independence remains limited to recorded exposures and self-reported flags, not observed offline help or an ability probability. History excludes answers, answer keys, source/grade snapshots, source paths and attachment keys.

## Official exam overlap gate

Persisted official-session problemOrder and draft-answer object keys now exclude known issued problems from fresh review selection, regardless of whether the old session finished. A matching official problem introduced after review creation is rechecked inside first-response handling and marks that first as assisted rather than independent. Closed private review keys and solutions are omitted for a matching current IN_PROGRESS official session with a null deadline or a future server deadline. Expired deadlines/submitted official sessions no longer block the private disclosure; history summaries remain available without source keys.
