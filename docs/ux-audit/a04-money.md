## 3. НЭГТГЭХ САНАЛАА

### Рекомендация: Нэг "Санхүүгэд" Орц + Дэд Табууд

**ADMIN-д:**

```
Удирдлага
├─ Санхүүгэд (шинэ супер-орц, 1 таб)
│  ├─ Төлбөр        (одоо /app/payments) ← TEACHER_PLUS эндээ
│  ├─ Банк тулгалт  (одоо /app/admin/reconcile)
│  ├─ Орлого/Зарлага (одоо /app/admin/finance)
│  └─ Төлбөр буцаалт (одоо /app/tuition)
├─ Дэлгүүр (шинэ орц, за /app/admin/store-г үзүүлэх)
├─ ...
```

**Эффект:**
- **Мөнгөний орцууд** 4 → 2 (Санхүүгэд + Дэлгүүр)
- **Таб нээх дхүйн шүбхүүлэлт** буурна
- **Давхарлалт** арилна (Төлбөр vs Банк тулгалт)

**Хожим давуу:** /app/payments ба /app/admin/reconcile хоёулаа ижил мөнгөтэй, гэхдээ:
- `/app/payments` → сурагч бүрийн төлбөрийн статус
- `/app/admin/reconcile` → банкны сүүл өгүүлэл

Дэд табуудт **хамтлаа нэг байр** → админ ойлгомжтой.

### Рекомендация: Дэлгүүр Харах Байдал

**Сонголт 1:** Нэг ADMIN-д харагдах `Дэлгүүр` орц (энгийн, цэвэр)
- STUDENT эндээс үүл → нуугдсан `/app/store`-ыг ашигла
- ADMIN `/app/admin/store`-г үзүүлэх

**Сонголт 2:** Давхар (одоо байх) → хоосон оруулах


Сонголт 1 нь дээр.

## 4. АЮУЛГҮЙ БАЙДАЛ — ЧУХАЛ АСУУДЛУУД

### 4.1 🔴 ЦАНАМХАЛ: Хоёр Төлбөр Хүлээн Авалт (Davkhap Darakh)

**Байршил:** `/app/buyer/page.tsx` строки 127–149

```javascript
async function pay() {
  if (paying) return;  // ← Зөвхөн CLIENT эндээр сэргийлнэ
  setPaying(true);
  try {
    await api("/payments", { ... });
    // ← Сүлжээ хоцорвол эхний POST сэвгэл гүйлгээсэнгүй
    // → браузер сэргээнэ → 2 дахь POST явж болно
```

**Томохон:** Race condition байж болно (2 төлбөр ЭЕГ гарсан).

**ЖИ:** 
- `Payment.providerPayiceId @unique` QPay-д сайн
- Гэхдээ BANK_TRANSFER методд ЯМАР ч шалгалт байхгүй → 2 төлбөр нэг утгаар орж болно

**Ялгавраа:** Банкны API нь идемпотент байх ёстой (оно давтагдахаасаа хамгаалах)

**Саналаа:** 
- (1) `PaymentCreationInProgress` токен → гүйлгээ завсарлагдсан эсэхээ сүүлд шалгах
- (2) Торолонгийн callback + polling dupicate дүчүү барих (STATUS.md §7.9-г үз)

---

### 4.2 🔴 ЦАНАМХАЛ: Буцаалтын Подтвержденияса Үгүй

**Байршил:** `/app/tuition/page.tsx` + `RefundCalculator` компонент

**Асуудал:**
- Админ "буцаалт" дарна → **ЭЭГ сурагчийн данс дөхөж явна** (ГҮЙЛГЭЭГ буцаах боломжгүй)
- Подтверждение үгүй (2-алхат, "Сайн үу?" товч)
- Хэдэн tögrög ирэх эсэхийг админ уг хэ дээр үзэхгүй

**Ялгавраа:**
- `RefundCalculator` нь үнэ *таб* гүйлгээнд дараа л гарна (зэвсэг сайн)
- Гэхдээ `/app/tuition` дээс шууд POST → өмнө нь баталгаажуулалт

**Саналаа:**
- (1) "Сайн үү?" модал → "X₮ [сур-ын нэр] буцаалтыг баталгаажуулаарай"
- (2) ADMIN БИШ TEACHER+-д хүргүүлэхгүй

---

### 4.3 🟠 ӨНДӨР: Сурагчийн ID-ын Харуулалт Үгүй Төлбөр Бүртгэлд

**Байршил:** `/app/admin/reconcile` + `/app/payments` дээр

**Асуудал:**
- Төлбөр бүртгэлд сурагчийн ФИ-г харуулахгүй, дүнд анхаарц → БУРУУ СУР-ИЙ ДАНС РҮҮ ШИЛЖҮҮЛЭХ

**Ялгавраа:** Bank reconciliation нь студент→төлбөр нь "утасны дугаар" дээр хийгддэг (STATUS.md §7.8 SMS), гэхдээ записи хүмүүс нь нэрээр үйлчилдэг.

**Саналаа:**
- Төлбөрийн мөрд: **"[Сур-ын нэр]"** + дүн + төлбөрийн мэдээлэл
- Хамтаж мартах ɔөрөгдмел: сурагчийн нэр → /app/admin/students дээр дахин шалгах (нэг алхам нэмэлт)

---

### 4.4 🟠 ӨНДӨР: Төлбөрийн Дүнгийн Валидац Дутуу

**Байршил:** `/app/buyer/page.tsx` + PaymentsClient + reconcile файлуудад

**Асуудал:**
- Минимум 1000₮ шалгалт (OK)
- **МАКСИМУМ шалгалт БАЙХГҮЙ** → админ 999,999,999₮ нэмэж болно
- **Мүнгөний символ ҮЗЭГДЭХГҮЙ** таб фильтр дээр (0.1₮ vs 1,000₮ оноо бүхэл байвал)

**Саналаа:**
- MAX шалгалт: толь сургалтын төлбөр ≤ 500,000₮ (цаашдын худагуу)
- Төлбөрийн мөр дээр: **"350,000₮"** эдгээр **сандалчныг** үзүүлэх (format дургуй)

---

### 4.5 🟡 ДУНД: `forMonth` Null Байж Болно Payment Дээр

**Байршил:** `schema.prisma` line 18 (Payment.forMonth String? — nullable)

**Асуудал:**
- Өгөгдмөл: "Энэ сарын төлбөр"
- Гарц: "Аль сарын төлбөр вэ?" хэмээх ЕРӨНХИЙ асуулт
- Reconciliation дээр сурагч "авах сар"-аа буруу ордог

**Саналаа:**
- `forMonth` заавал бөглөнө (NOT NULL)
- UI дээр: "Төлбөрийн сар" dropdown (одоогийн сар = сонголт)

---

### 4.6 🟡 ДУНД: QPay Callback Дахин Ирсэн үед

**Байршил:** `schema.prisma` line 21 (`providerPaymentId @unique`) — САЙН, гэхдээ...

**Асуудал:**
- Хэрэв callback ДАХИН ирвэл (эсвэл polling + callback хоёулаа) → Payment.status "PENDING" → "PAID" → "PAID" (идемпотент, сайн)
- ГЭХДЭЭ Purchase үүснэ 2 удаа байж болно (STATUS.md §7.9 дээр анхнуу)
- Хэзээ "гарна" мэдэгдэх (callback явсан эсэх)

**Саналаа:**
- StatusCheck бичлэг: Payment callback дууссан заалт (үүлийн дээрэх)
- UI дээр: "📳 QPay хүлээж байна" vs "✅ Өгүүлэлтүүд ба туг нээгдлээ"

## 9. НӨХЦӨЛ ӘҮ: ТУЛИНКИЙН ЖАГСААЛТ, ЗӨВ БАЙДЛЫН ЭРЭМБЭ

### 🔴 ЧАНАМХАЛ (2 АСУУДАЛ)

1. **Төлбөрийн Хоёргүйн Эрс**: `Payment.providerPaymentId @unique` сайн, гэхдээ BANK_TRANSFER методогд 100% идемпотент биш. Гүйлгээг дахин явлалгүй байх хэрэгтэй (ажилтан × банк callback → 2 төлбөр орж болно).

2. **Буцаалтын Хэргэм Подтвер-дение**: `/app/tuition` admin POST сумын үгүй. Сурагчийн данс ухаалсагч байж болно → 100% буцаагдаахгүй.

### 🟠 ӨНДӨР (2 АСУУДАЛ)

3. **Сурагчийн нэр-ID-ын харуулалт töлбөр мөрд**: хүрч авалтгүй. Буруу орц явж болно.

4. **Төлбөрийн дүнгийн MAX валидац**: 999,999,999₮ оруулж болно. MIN (1000₮) зөвхөн.

### 🟡 ДУНД (2 АСУУДАЛ)

5. **`forMonth` NULL байж болно**: заавал байх ёстой (бүмүүнс сарын төлбөрийн үндэс).

6. **QPay callback дахин ирсэн үед**: Purchase давхараа үүссэн байж болно. Идемпотент шалгалт (STATUS.md §7.9) сайн гэхдээ CLI feedback дутуу.

## 12. ХҮРГҮҮЛЭЛТ: 12 МӨРӨН ХУРААЛГА

1. **Хүрч авалтгүй хуудсууд (4):** `/admin/finance`, `/admin/store`, `/tuition`, `/store` — бүгд БҮРЭН ГОТОВО, компонент гүйлгээтэй, зөвхөн navиагация орцход оруулалт дутуу.

2. **Дээр оруулалт:** `/admin/store` → ADMIN-д; `/tuition` → ADMIN-д (эсвэл reconcile дэд таб); `/admin/finance` → ADMIN-д.

3. **Мөнгөний орцууд:** 4 (Төлбөр, Банкны тулгалт, + 2 нуугдсан) → **2 саналаа** (Санхүүгэд + Дэлгүүр) хүргүүлэхээр.

4. **Аюулгүй байдал (цанамхал):** Төлбөрийн хоёргүй рас (`Payment.providerPaymentId @unique` сайн, гэхдээ BANK_TRANSFER идемпотент үгүй). Буцаалтын подтвер-дение үгүй.

5. **Нэр-ID харуулалт:** Төлбөрийн мөрд сурагчийн нэр ҮЗЭГДЭХГҮЙ → буруу орц явж болно.

6. **Алхам хэмнэлт:** "Төлбөргүй сурагч олох" (одоо 4 алхам) → фильтр нэмэхэд 3 болно. "Төлбөр бүртгэх" (5–6) → подтвер-дение нэмэхээ нөлөө.

7. **Орцын саналаа:** Одоо 3 мөнгөний орц (Төлбөр + Банк + нуугдсан Финанц) → 1 "Санхүүгэд" орц + 4 таб = ᠶүүлэлт сайн (улаан мөрд хэмнэлт).

8. **Дэлгүүр:** `/store` vs `/admin/store` хоёулаа готово, хэд хоёулаа navиагациид үгүй → нэгээр ADMIN-д үзүүлнэ (судалж эхлүүлэх).

9. **Навагационн шаңгүй:** Одоо 4 "цэвэрхэн орцойго" нуугдсан → 2-оор (finance, store) үзүүлэхээр → бөмбөлөл хэмнэлт.

10. **Хүрч авалтгүй = цилиндр:** /app/tuition (буцаалт) орц үсэй даа сав оруулсаагүй → Ажилтан түүнийг олдохгүй, "ахиад сэргээнэ?" гэж сэтгэж болно.

11. **Өргүүлсэл:** Төлбөр бүртгэлд максимум дүн валидац, forMonth заавал байх, QPay callback идемпотент (STATUS.md §7.9-г сайжруулах).

12. **Шийдвэр:** Сонголт B (4 хуудсанг навигациид оруулах) эцэг авах боломжтой; "Санхүүгэд" супер-орцын дэд таб сонголт A-ыг хэрэгжүүлнэ, хэзээ нь эзэн юу хүсэхийг нарьял авчрахбал сайн.
