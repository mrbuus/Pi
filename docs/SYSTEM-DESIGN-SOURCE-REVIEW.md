Мөрийн тоонд гарчиг/тайлбар орно; сурагчийн тоо биш. Нэг хүнийг хэд хэдэн sheet-д хуулсан тул бүх sheet-ийн мөнгийг шууд нийлүүлж орлого гэж тооцохгүй. Нормчилсон овог/нэр давтагдсан253 бүлэг илэрсэн нь давхар төлбөрийн нотолгоо биш. Сар бүрийн amount/coverage period/receipt талбаруудыг Payment, BillingPeriod, Allocation, ReceiptReference болгон салгана. Хоосон боловч форматтай 318 баганатай extent нь бодит318 өгөгдлийн багана гэсэн үг биш.

Cached formula error олдоогүй; Excel-ийг дахин тооцоолж санхүүгийн үнэн зөвийг батлаагүй. Чөлөөт текст, хуучин/шинэ сурагч, өөр төрлийн тариф, Excel date болж хувирсан ангийн код зэрэг нь migration preview шаарддаг. Receipt date ганцаараа банкны тогтвортой transaction ID биш.

**Хоёр тусдаа migration:** (1) одоогийн workbook-оос баталсан төлсөн түүх, invoice, эхний өр/авлага, илүү төлөлт; (2) шинээр орж ирэх банкны хуулгыг өдөр тутам тулгах. Шинэ банкны хуулгын бодит файл ирээгүй тул баганын adapter болон банкны нийт дүнтэй тааралтыг одоо баталсангүй.

Багш+: өөрийн ангийг нээнэ → төлбөрийн badge → due/paid/balance харна. Санхүүгийн эрхтэй Багш+: хуулга оруулна → **таарсан / дутуу / илүү / олон хүүхэд / тодорхойгүй / давхардал** гэсэн тексттэй өнгийн төлөвүүд → сонгож батална → нэг transaction-д Payment+Allocation+audit. Бусад багшид банкны бүх мэдээллийг өгөхгүй.

## Notebook яг юу хийдэг вэ?

Машиныг удирдах эсвэл цааснаас зураг таних код биш. Машины гаргасан Excel хариулт + `key.ini` → ID тулгалт → оноо → Scores/Answers/Analyze болон өнгө/эрэмбэлсэн Excel. `Scored_Data.xls/xlsx`, `key.ini` хавсаргаагүй учир бодит grading-г энэ удаад ажиллуулаагүй.

Сонгох хэсэг: зөв таарсан асуултын weight. Нөхөх хэсэг: бүлгийн **бүх нүд** зөв үед group score; хэсэгчлэн зөвийг нүдний тайланд харуулах ч group оноо өгөхгүй. Total/max ба section totals хадгална. Saved output-д30 мөрийн үр дүн,27 exact+3 whitespace fix,0 unmatched гэж байгаа; энэ нь өмнөх run-ийн түүх.

| Эх кодын зан үйл | Төлөвлөсөн хамгаалалт / шалгуур |
|---|---|
| Unknown variant →0 оноо | **OM04:** алдааны мөр тусгаарлаж key батлахаас өмнө дүн болгохгүй |
| Total score mismatch зөвхөн warning | Key maximum зөрвөл импорт/нийтлэл хаах |
| Duplicate registry эхний мөрөө авах | **OM03:** duplicate ID blocker, давхар scan review |
| Урт хариуг тайрах/богиныг нөхөх | **OM02/06:** form layout-аар урт, тэмдэг шалгах |
| Whitespace элбэг байрлалыг separator гэж таах | **OM05:** маягтын version-ы explicit байрлал; хоосон хариуг шилжүүлэхгүй |
| Эхний sheet л оноолох | Sheet сонголт ба omitted row count preview |
| A/B нэг дугаарыг нийлүүлж ALL дүн | **OM08:** ижил questionId эсэхийг тулгаж байж нийт mastery гаргах |
| Excel экспорт | **OM09–11:** private preview → approve → дүнгийн revision → тусдаа нийтлэх |

Хэрэгжүүлэх QA: зөв дүгнэсэн жишиг файл, буруу key, танигдахгүй ID/variant, давхар scan, хоосон/илүү тэмдэг, тасарсан файл, давтан импорт, regrade. Expected оноог багшийн гараар бодсон түүвэртэй тулгана.

## Өрсөлдөгчийн судалгаа → шалгалтын стратеги

Өмнөх `market-research/2026-09-15-MARKET-RESEARCH-FINAL.md`-ийн таамгийг дараах нийтийн үйлчилгээгээр дахин тулгав: [YESH timed сорил](https://yesh.mn/quick-test), [iMath](https://imath.mn/), [Lumina жишиг сорил](https://www.lumina.mn/mock-test). Эдгээр нь сайт дээр санал болгож буй функц; хэрэглэгчийн тоо/үр дүн/орлогын бие даасан баталгаа биш. Хуучин хичээлийн жилийн үнийг2027 тариф гэж аваагүй.

**ST01–07 санал:** OMR ба онлайн шалгалтын дүн → нэг сурагчийн түүх → алдсан сэдэв → багшийн дараагийн ажил. Үнэгүй жижиг diagnostic, нэг paid on-demand, жижиг live event-ээр offer туршиж; import mismatch, payment success, completion, result latency, refund/support, дараагийн ажлын гүйцэтгэлийг хэмжинэ. Live event-ийн анхны оролдлогын rank, on-demand retry/best rank-ийг нийлүүлэхгүй. Нэрийн жагсаалтыг нийтлэх сонголт ба хариу/бодолт ил гаргах цаг тусдаа.

## Нэвтрүүлэх дараалал ба шаардлагатай шийдвэр

1. **P0 — баримт/гэрээ:** 2027 шинэ үнэ, гэрээний огноо, өвчин/чөлөө, grace boundary, due31-ийн богино сарын дүрэм; бодит банкны хуулга ба OMR golden files; ID mapping review.
2. **P1 — суурь:** тогтвортой userId, studentCode history, staff scope, contract/invoice/payment/allocation, content version, media төрөл, audit; өгөгдлийн migration preview.
3. **P2 — ангийн өдөр тутам:** нэг багц сонголт, submitted counts, даалгавар→алдаа засах→зураг→багшийн эцсийн дүн; онол/нөхөлт.
4. **P3 — санхүү ба OMR pilot:** хуулга→review→батлах, invoice shadow calculation; дараа нь зөв тооцож байгааг батлаад төлбөрийн хаалт; OMR private дүн→нийтлэх preview.
5. **P4 — paid exam:** merchant нөхцөл, credit хүрээ, ledger concurrency/refund; on-demand pilot→live pilot→1000 зэрэг оролцогчийн ачааллын шалгалт.
6. **P5 — өргөжүүлэх:** банкны feed, олон хичээл/mobile, хэмжсэн p95/SLO, backup restore, incident/regrade drill.

Хэрэгжүүлэхийн өмнөх шийдвэрүүдийг одоохондоо таамгаар батлаагүй. Энэ нь төлөвлөгөөг гаргахыг зогсоох шалтгаан биш: блок бүрийн acceptance, өгөгдөл, actor, алдаа, дараагийн ажлыг backlog-д оруулсан.
