Тусдаа HTML туршилтын шинэчлэл · 2026-10-06\text{2026-10-06}. Үндсэн Pi.mn, API, өгөгдлийн санг өөрчлөөгүй. Доорх сервер, түвшний загварууд төлөвлөгөө.

Хүүхэд юу хардаг вэ?

Хичээл

Сэдэв, ажлын хэмжээ, эхлэх товч. Онолыг хүссэн үедээ нээнэ. Нөхөлтийн үед онолыг эхлээд уншина.

Нэг бодлого

Сангийн LaTeX бодлого, хариуны талбар/сонголт, Дараах. Сүүлчийн бодлогод дуусгах товч.

Үр дүн

Анхны зөвийн тоо, шалгах бодлого. Алдаатайг дахин бодох хэсэг. Бодолт, бүрэн түүх, тусламжийн мэдээллийг нээнэ.

Бодлогын дугаарууд, эх сурвалж/ID, итгэл/тусламжийн тэмдэглэл, виртуал тохиргоо, багш ба эцэг эхийн цонх тусдаа эвхэгдэнэ. Боломжуудыг устгаагүй. Тэмдэглэл нээсэн хүүхдийн сонголтыг бодлого хооронд хадгална; тэмдэглээгүй итгэлийг систем өөрөө зохиохгүй.

Танхим, онлайн, нөхөлтийн ялгаа
  • Танхим: ангид утасгүй хийсэн анхны хариугаа гэрт хуулна. Өмнөх бодолтын хурдыг энэ хугацаанаас мэдэхгүй.
  • Онлайн: бодлогыг анх харснаас өөрийн хариуг оруулах хүртэлх браузерын үйлдэл ажиглагдана. Гаднах тусламж, цаасан бодолт, тасалдлыг бүрэн мэдэхгүй.
  • Нөхөлт: ирц хэвээр, онол уншсан тэмдэглэгээ ба нөхсөн өдөр тусдаа. “Уншсан” товч ойлгосны баталгаа биш.
  • Давтлага: багцаа сонгосны дараа тохиргоонуудын оронд нэг бодлого харагдана. Шинэ нөхцөл ба өмнөх алдааг ялгана.

Хугацааны хэмжилтийн үндэслэл

Богино интервалд performance.now() ашиглана. Энэ нь monotonic бөгөөд системийн ханын цагийн засвараас тусдаа; компьютер унтах үед браузер/үйлдлийн системийн зан төлөв ялгаатай байж болно. Reload-оос өмнөх monotonic timestamp-ийг дараахтай нь шууд хасахгүй. MDN: performance.now().

visibilitychange, фокус алдах, хэрэглэгчийн түр завсарлах үйлдэлд хугацааг хаана. Tab харагдах нь фокустай гэсэн үг биш, фокус алдах нь tab нуугдсан гэсэн үг биш. Background timer-ийн давтамжид найдахгүй; интервалын эхлэл/төгсгөлийг хэмжинэ. MDN: Page Visibility API.

Алдаа/зөв ба хариуны хугацааг ялгаж загварчлах суурь нь van der Linden-ийн шаталсан хүрээтэй нийцнэ: чадвар болон хурд тусдаа параметр. Энд зөвхөн өгүүллийн abstract-ыг шалгасан; Bayesian загварыг хэрэгжүүлсэн, эсвэл манай хүүхдэд хүчинтэй гэж мэдэгдээгүй. Дараа нь хүүхдийн түвшинд яаж ашиглах вэ?

  1. Нотолгоогоо ялгана. Анхны зөв/буруу, таасан/эргэлзсэн, тусламжтай, бодолт өмнө үзсэн, хуучин/шинэ бодлого, чиглүүлэх алхамтай/алхамгүйг холбоно.
  2. Сэдэв, аргын түвшинд эхэлнэ. Нэг сонголтыг зөв таасан хүүхдийг бүх сэдэв сайн гэж нэрлэхгүй. Буруу аргыг давтах санал; өгөгдөл бага бол “хангалттай мэдээлэлгүй”.
  3. Хугацааг туслах шинж болгоно. Зөв/буруугаас тусдаа тайлбарлаж, бодлогын хүндрэл, харагдац, төхөөрөмж, унших/оруулах ачааллыг тооцно. Хурдан буруу, удаан зөв, тусламжтай хурдан зөвийг ялгана.
  4. Багштай тулгана. Шинэ бодлогыг тусламжгүй бодсон, хугацааны дараа дахин хийсэн болон багшийн ажиглалтаар загвараа шалгана. Хүүхдийг хурдан/удаан гэсэн шошгоор эрэмбэлэхгүй.
  5. Калибровк хийнэ. Өөр хүүхэд, өөр бодлого, өөр өдөрт шалгах holdout хэрэгтэй. Алдааны хэмжээ, итгэлцлийн интервал, төхөөрөмжөөс үүдсэн зөрүү, missingness, cold start-ыг тайлагнана.

Энэ хувилбарт чадварын магадлал, IRT оноо, автомат хүүхдийн ангилал үүсгэхгүй. Урьдын алдаа/эргэлзээнээс давтах аргыг сонгох дүрэм хэвээр. Хугацааны шинэ өгөгдлийг хожмын загварт ашиглах зам болон чанарын тэмдэглэгээ нэмсэн.

Серверийн ачаалал бага байлгах төлөвлөгөө

Одоо: гадаад хүсэлт тэг; нэг HTML, локал KaTeX → MathML, локал хадгалалт. Хэрэглэгчийн оролтын хадгалалтыг нэг секундээр debounce хийнэ; шилжилт, pagehide, экспорт дээр flush хийнэ. Бодлогын active хугацааг богино checkpoint-оор нэмж, tab нуугдсан/фокусгүй мөчийг нэмж тооцохгүй.

Нэг run-д сүүлийн 20002000 semantic үйлдэл, хамгийн их 800800 асуулт/үеийн хэмжилт үлдээнэ. Хязгаараас гарсан тоог хадгалж, мэдээлэл дутсан гэдгийг ил гаргана. Энэ нь урт хугацааны үйлдвэрлэлийн суралцах түүхийн бодлого биш. Full run JSON экспортод хариу ба хугацааны бүртгэл хамт орно.

Жинхэнэ API холбох үед хийх ажил
  • Браузерт buffer → 10–30\text{10–30} секунд эсвэл тодорхой хэмжээний batch → хариу өгсөн дарааллыг батлах. Нэг товч бүрээр серверт хүсэлт илгээхгүй.
  • Authentication-тай хүүхдийн ID-г серверт холбоно; браузерын self-report-оос багш/эцэг эхийн эрх гаргахгүй. Тусдаа ангийн access scope.
  • eventId = learner/session/sequence эсвэл UUID-тай unique constraint; offline retry давхар үйлдэл болгохгүй. Client clock нь шалгалтын server deadline-ийн эх сурвалж биш.
  • Oролтын schema, batch size, payload size, timestamp sanity шалгах. Түүхий telemetry-ийг шалгалтын дүнгийн transaction-оос тусад нь хадгална.
  • Үйлдлийн raw retention-ийг зөвшөөрөлтэй тодорхойлж, урт хугацаанд утгатай нийлбэр хадгална. Зөвхөн хэрэгтэй бүлгийн багш хүүхдийн мэдээлэлд хандана; export/delete шаардлага тусдаа.
  • Ачаалал, сүлжээ тасрах, retry, duplicate, clock drift, event loss-ыг туршина. Redis/queue хэрэгтэй эсэхийг хэмжилтээр шийднэ; энэ HTML-д backend байгуулаагүй.

Шалгах зүйл, бодит хязгаар

Одоогийн гүйцэтгэсэн шалгалт: хуучин сургалтын урсгалууд, цөөн үндсэн үйлдэл, завсарлага/blur/reload, semantic үйлдлийн хязгаар, LaTeX preview, export, утасны overflow.

Жинхэнэ хүүхдийн дундаж бөглөх хугацаа, ойлгомжтой байдал, хөгжлийн үр дүн одоогоор хэмжээгүй. Safari-ийн хэрэгжилтийг ажиллуулж батлаагүй; хэрэглэгчийн Safari туршилт тусдаа хэрэгтэй. Автомат Chrome шалгалт нь эдгээрийг орлохгүй.

Номын бодлогуудын эх сурвалж, 5050 эх ба 6060 шинэ тоон жишээ өмнөх тусдаа баталгаажсан сангаас ирнэ. Хариуны текст оролт өөрөө энгийн editable талбар; түүний доор LaTeX preview гарна. Бусад бодлого, шийд, дүнгийн тоо MathML-ээр дүрслэгдэнэ.
