# Piemath — гар утасны апп болгох төлөвлөгөө

Огноо: 2026-11-01 · Төлөв: санал (шийдвэр гараагүй) · Дэлгэрэнгүй: [MOBILE-APP-DETAIL.md](MOBILE-APP-DETAIL.md)

## 1. Одоогийн байдал (кодоос харсан)

- **web/** — Next.js 16 + React 19, ~113 хуудас (`page.tsx`)
- Тусгай сангууд: **KaTeX** (томьёо харуулах), **MathLive** (томьёо бичих), **three.js** (3D), **pdf-lib** (PDF)
- **api/** — NestJS + JWT + Prisma/Postgres, AWS EC2 дээр. Апп ямар ч технологиор хийгдсэн
  энэ API-г шууд ашиглана — сервер талд бараг өөрчлөлт хэрэггүй

Гол асуулт: **113 хуудсыг дахин бичих үү, эсвэл байгааг нь утсанд оруулах уу?**

## 2. Сонголтууд

| | PWA | Capacitor (одоогийн веб + натив бүрхүүл) | Flutter (бүрэн дахин бичих) | React Native / Expo |
|---|---|---|---|---|
| Кодын дахин ашиглалт | 100% | ~95% | 0% UI (API л) | Логик хэсэгчлэн, UI дахин |
| Хугацаа (ойролцоо) | 1–3 өдөр | 2–4 долоо хоног | 4–8+ сар | 3–6 сар |
| App Store / Play | Үгүй (Play-д TWA-аар болно) | Тийм | Тийм | Тийм |
| Push мэдэгдэл | Android сайн, iOS сул | Бүрэн натив | Бүрэн | Бүрэн |
| LaTeX / MathLive | Байгаагаараа | Байгаагаараа | **Хамгийн хэцүү** — доор харна уу | WebView хэрэгтэй |
| Засвар хийх | 1 газар | 1 газар | **2 газар** (веб + Dart) | 2 газар |
| Гүйцэтгэл | Веб | Веб (хангалттай) | Хамгийн гөлгөр | Натив |

### Flutter-ийн хэцүү цэгүүд (шийдэхээс өмнө мэдэх)

1. **Томьёо харуулах** — `flutter_math_fork` KaTeX-ийн бүх командыг дэмждэггүй. Манай 12,000+
   бодлогын LaTeX-ийн нэг хэсэг зөв харагдахгүй байх эрсдэлтэй → бодлого бүрийг дахин шалгах
2. **Томьёо бичих (MathLive)** — Flutter-т `math_keyboard` сан бий, гэхдээ MathLive-аас хязгаартай → дутууг нь нэмж хөгжүүлнэ ([MOBILE-SCAN.md](MOBILE-SCAN.md))
3. **113 хуудас** + багш/админы самбар, ирц, төлбөр, хуваарь — бүгдийг Dart-аар дахин
4. Шинэ функц бүрийг **хоёр удаа** бичнэ (веб ба апп) — нэг хүний багт хамгийн том зардал

Flutter-ийг сонгох үндэслэлтэй үе: апп нь веб-ээс **өөр**, жижиг, хурдан туршлага байх
(жишээ нь зөвхөн сурагчийн «бодлого бодох + даалгавар илгээх» апп) бол.

## 3. Зөвлөмж: үе шаттай

### Үе 0 — PWA (1–3 өдөр)
- `manifest.json`, иконууд (байгаа), service worker → «Нүүр дэлгэцэд нэмэх»
- Сурагчид маргаашнаас апп шиг ашиглана; ямар ч дэлгүүрийн хяналтгүй

### Үе 1 — Capacitor апп (2–4 долоо хоног)
- `web/`-ийг Capacitor-оор iOS + Android болгох (pimath.mn-ийг ачаалах эсвэл статик bundle)
- Натив нэмэлтүүд (Apple «зүгээр л вэбсайт» аппыг буцаадаг — 4.2 дүрэм, тиймээс эдгээр заавал):
  - **Push мэдэгдэл** (FCM/APNs) — даалгавар, ирц, төлбөрийн сануулга
  - **Камер** — даалгаврын зураг илгээх (одоогийн 6 хуудасны PDF урсгал)
  - **Google нэвтрэлт** — Google WebView доторх OAuth-г хориглодог → натив plugin эсвэл системийн хөтөч
  - Deep link (`pimath.mn/...` холбоос аппад нээгдэх)
- API талд: push token хадгалах хүснэгт + мэдэгдэл илгээх сервис

### Үе 2 — Дэлгүүрт гаргах (1–2 долоо хоног, хяналт хүлээх хугацаа орно)
- Apple Developer **$99/жил**, Google Play **$25 нэг удаа**
- Нууцлалын бодлогын хуудас, **апп дотроос бүртгэл устгах** (Apple заавал шаарддаг)
- Хэрэглэгчид хүүхэд → «Kids» ангилалд биш, «Education»-д; хүүхдийн өгөгдлийн дүрмийг анхаарах
- Анх TestFlight / Play internal testing-ээр багш нар, хэдэн сурагч дээр турших

### Үе 3 — (сонголтоор) Натив/Flutter
- Хэрэглээний статистик гарсны дараа хамгийн их ашиглагддаг 2–3 дэлгэцийг (жишээ нь
  бодлого бодох) натив болгох эсэхийг шийдэх. Энэ үед Flutter-ийг тусдаа «сурагчийн апп»
  хэлбэрээр авч үзэж болно.

## 4. Cloud session ашиглах

- Боломжтой: репо GitHub дээр байгаа (`mrbuus/Pi`) — cloud session түүнийг clone хийж,
  тусдаа branch дээр ажиллаж PR нээнэ
- Энэ нь Claude-ийн ижил бүртгэлийн хэрэглээ (usage/credit)-ээс хасагдана — үлдэгдлээ
  Claude-ийн тохиргооны Usage хэсгээс шалгана
- Хязгаар:
  - Cloud орчин нь **Linux** → **iOS build, iOS simulator боломжгүй** (macOS + Xcode хэрэгтэй).
    Код бичих, `flutter analyze`/тест, Android build-ийг тохируулбал хийж чадна
  - Таны локал DB, прод сервер рүү хандахгүй — энэ нь сайн (прод өгөгдөлд хүрэхгүй)
  - Эцсийн туршилт, дэлгүүрт гаргахыг энэ Mac дээр хийнэ
- Тохиромжтой хуваарилалт: cloud — шинэ код бичих (Capacitor тохиргоо, push сервис, эсвэл
  Flutter дэлгэцүүд); энэ Mac — simulator, жинхэнэ утсан дээр турших, store-д илгээх
