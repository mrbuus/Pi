# Гар утасны апп — 4 замын дэлгэрэнгүй тайлбар

Огноо: 2026-11-01 · Хураангуй: [MOBILE-APP-PLAN.md](MOBILE-APP-PLAN.md)

Эзний нөхцөл: хугацаа, мөнгө асуудал биш. Зорилго — апп **хамгийн гөлгөр** ажиллах,
утасны өөрийн процессорыг ашиглах.

---

## 0. Эхлээд хоёр ойлголтыг тодруулъя

### 0.1 Flutter «утасны натив хэл» мөн үү?

Яг тийм биш, гэхдээ гүйцэтгэлийн хувьд маш ойр.

| | Жинхэнэ натив | Flutter | Веб (PWA, Capacitor) |
|---|---|---|---|
| Хэл | Swift (iOS), Kotlin (Android) | Dart | JavaScript/TypeScript |
| Хөрвүүлэлт | ARM машин код | **ARM машин код (AOT)** | Ажиллах үедээ JIT |
| Дэлгэц зурах | iOS/Android-ийн өөрийн товч, жагсаалт | **Өөрийн зураглагч (Impeller)** пиксел бүрийг зурна | Хөтчийн HTML/CSS |
| Код бичих | 2 удаа (iOS + Android тусад нь) | **1 удаа** | 1 удаа |
| Гөлгөр байдал | 120 fps | 60–120 fps | 60 fps хүртэл, хүнд хуудсанд гацна |

Flutter нь хоёр платформд нэг кодоор бараг натив хурдтай ажилладаг. Тиймээс гөлгөр байх
зорилгод Flutter зөв сонголт. Swift + Kotlin-оор тусад нь бичвэл бага зэрэг илүү гөлгөр
болох ч ажил хоёр дахин их.

### 0.2 «Утасны процессороор тооцоолуулбал ачаалал багасна» гэдэг

Тооцоолол хоёр газар явагддаг:

```
Утас (клиент)                         Сервер (AWS EC2 + RDS)
- Дэлгэц зурах, хөдөлгөөн             - Нэвтрэлт, эрх шалгах
- Томьёо харуулах                     - Шалгалтын хариу шалгах, оноо
- Зураг шахах (даалгавар)             - Ирц, төлбөр, даалгавар хадгалах
- Офлайн кэш, таймер                  - Бодлогын сан, хариуны түлхүүр
```

- **Веб апп ч бас утасны процессор дээр ажилладаг.** Ялгаа нь: веб нь JavaScript-ээр,
  хөтчийн дотор явагддаг тул удаан. Flutter нь машин кодоор шууд ажилладаг тул хурдан
  бөгөөд батарей бага иднэ.
- **Утсанд илүү их ажил өгөх нь серверийн ачааллыг бууруулна, утасных нэмэгдэнэ.**
  Жинхэнэ хэмнэлт нь **кэшээс** гардаг: бодлогыг нэг удаа татаад утсанд хадгалбал
  дахин дахин сервер рүү хандахгүй. Үр дүнд нь сервер ч, интернэтийн дата ч хэмнэгдэнэ.
- **Анхаар:** **Хариу шалгахыг утсанд шилжүүлж болохгүй.** Хариуны түлхүүр утсанд очвол сурагч
  аппыг задлаад хариуг харж чадна. Оноо, эрх, төлбөр үргэлж сервер дээр үлдэнэ.

## 1. PWA (Progressive Web App)

### Юу вэ
Вэбсайтыг утасны нүүр дэлгэцэд апп шиг дүрстэй суулгах арга. Хөтчийн хаяг байхгүй,
бүтэн дэлгэцээр нээгдэнэ. Дэлгүүр хэрэггүй.

### Манайд аль хэдийн байгаа зүйл (кодоос шалгасан)
- `web/src/app/manifest.ts` — апп-ын нэр, өнгө, иконууд
- `web/public/icons/` — 192, 512, maskable иконууд
- `web/public/sw.js` — service worker: нийтийн файлууд болон томьёог кэшлэх, `/offline` хуудас

Тэгэхээр PWA бараг бэлэн. Үлдсэн ажил:
1. Суулгах боломжтой эсэхийг Chrome DevTools → Lighthouse-оор шалгах
2. iPhone хэрэглэгчдэд «Share → Add to Home Screen» гэсэн заавар харуулах (iOS автомат
   товч гаргадаггүй)
3. (сонголтоор) Web Push — iOS 16.4+ дээр зөвхөн нүүр дэлгэцэд суулгасан PWA-д ажиллана

### Давуу ба сул тал
- Давуу: 1–3 өдөр, үнэгүй, веб засагдахад шууд шинэчлэгдэнэ
- Сул: App Store-д гарахгүй, iOS-ийн push сул, гүйцэтгэл нь веб хэвээр

### Flutter-тэй хамт ямар үүрэгтэй вэ
Flutter апп бэлэн болтол (хэдэн сар) сурагчид PWA-г ашиглана. Үргэлж хэрэгтэй.

## 2. Capacitor

### Юу вэ
Одоогийн веб-ийг натив «бүрхүүл» (iOS-д WKWebView, Android-д WebView) дотор оруулж,
дэлгүүрт гаргах апп болгох. JavaScript-ээс камер, push зэрэг натив боломжийг
plugin-оор дуудна.

```
┌────────── iOS / Android апп ──────────┐
│  Натив бүрхүүл (Swift / Kotlin)        │
│   ├─ Push, Камер, Google нэвтрэлт      │  ← plugin-ууд
│   └─ WebView ──► pimath.mn (Next.js)   │  ← одоогийн 113 хуудас
└────────────────────────────────────────┘
```

### Хоёр горим
- **Remote URL** — апп pimath.mn-ийг ачаална. Веб deploy хийхэд апп шууд шинэчлэгдэнэ.
  Интернэтгүй үед ажиллахгүй.
- **Bundled** — веб-ийг статик файл болгож апп дотор хийнэ. Next.js-ийн динамик
  маршрутуудаас болж `output: 'export'` руу шилжүүлэх ажил их.

### Хийх ажил
1. `npx cap init`, `ios/`, `android/` төслүүд үүсгэх
2. Plugin-ууд: `@capacitor/push-notifications`, `@capacitor/camera`, Google нэвтрэлтийн
   натив plugin, app links (deep link)
3. API: `DeviceToken` хүснэгт, мэдэгдэл илгээх сервис (FCM)

### Яагаад Flutter-ийн оронд сонгохгүй байж болох вэ
Гөлгөр байдал нь веб хэвээр. Эзний зорилго гөлгөр байдал тул **Flutter-ийг сонговол
Capacitor-ийг алгасаж болно.** Capacitor-ийн хийх push, Google нэвтрэлт, камер,
дэлгүүрийн ажлыг Flutter-т мөн хийнэ.

## 3. Дэлгүүрт гаргах (Flutter, Capacitor аль алинд нь ижил)

### 3.1 Бүртгэл
| | Apple Developer | Google Play Console |
|---|---|---|
| Үнэ | $99/жил | $25 нэг удаа |
| Байгууллагаар бүртгүүлэх | **D-U-N-S дугаар** хэрэгтэй (үнэгүй, 1–2 долоо хоног) | D-U-N-S хэрэгтэй |
| Хувь хүнээр | Дэлгүүрт хувь хүний нэр харагдана | **12 тестертэй 14 хоногийн хаалттай тест** заавал хийнэ |

→ «Шинэ ирээдүйн эзэд» нэрээр **байгууллагын бүртгэл** нээхийг зөвлөж байна.
Дэлгүүрт сургалтын төвийн нэр харагдана, Google-ийн 14 хоногийн шаардлага хамаарахгүй.

### 3.2 Шаардлагууд
- **Нууцлалын бодлого** — нийтэд нээлттэй URL (жишээ нь `pimath.mn/privacy`)
- **Апп дотроос бүртгэл устгах** (Apple 5.1.1(v)). Анхаар: Манай прод өгөгдлийн дүрэмтэй
  зөрчилдөхгүйн тулд: «устгах хүсэлт» → зөөлөн устгал (deletedAt) + админ шийдэх
  урсгал. Хуулиар хадгалах ёстой төлбөрийн бичлэг үлдэнэ гэж бодлогод бичнэ
- **Sign in with Apple** (Apple 4.8) — Google нэвтрэлт байгаа бол түүнтэй тэнцэх өөр
  сонголт заавал. Шийдэл: iOS-д «Sign in with Apple» нэмэх
- **Хүүхдийн өгөгдөл** — «Kids» ангилал биш, «Education». Google Play-д «Target audience»
  асуулгад насны ангиллыг үнэн зөв бөглөнө (13-аас доош сонговол Families бодлого хамаарна)
- App Privacy (Apple), Data safety (Google) маягт: утас, нэр, зураг цуглуулдаг гэдгийг бичнэ
- Скриншотууд (6.7", 5.5" iPhone, iPad), Play-д feature graphic

### 3.3 Хяналт ба шинэчлэл
- Apple-ийн хяналт ихэвчлэн 1–3 өдөр, эхний удаа татгалзаж магадгүй
- Flutter-т шинэчлэл бүр дахин хяналтад орно. Хурдан засвар хэрэгтэй бол **Shorebird**
  (Flutter-ийн code push) ашиглаж Dart кодыг дэлгүүргүйгээр шинэчилж болно

## 4. Flutter апп — дэлгэрэнгүй

### 4.1 Хамрах хүрээ
| Хэрэглэгч | Хаана |
|---|---|
| **Сурагч** | Flutter апп (гол) |
| **Эцэг эх** | Flutter апп (сурагчийнхтай нэг апп, эрхээр ялгана) |
| Багш | Эхлээд веб. Дараа нь «ирц тэмдэглэх, даалгавар шалгах»-ыг аппад нэмж болно |
| Багш+, Админ | Веб хэвээр (тайлан, төлбөр, импорт — том дэлгэцэд тохиромжтой) |

113 хуудсыг бүгдийг биш, **сурагч, эцэг эхийн хэрэглэдэг хэсгийг** бичнэ.
Админы хэсэг аппад хэрэггүй. Энэ нь ажлыг ойролцоогоор гуравны нэг болгоно.

### 4.2 Сурагчийн дэлгэцүүд (эхний жагсаалт)
1. Нэвтрэх (утас + нууц үг, Google, Apple)
2. Нүүр — өнөөдрийн хичээл, даалгавар, мэдэгдэл
3. Миний анги (`/app/my-class`) — онолын зураг, даалгавар 7 хоногоор
4. Даалгавар илгээх — **натив камер**, 6 хуудас, зураг шахах, дахин илгээх
5. Тест / шалгалт бодох — A–E сонголт, таймер, офлайн үргэлжлэх
6. Бодолт харах (7 хоногийн дараа нээгдэх дүрэм), YouTube
7. Ном (`/books`), жишиг сорил (`/sorils`), түвшин тогтоох (`/placement`)
8. Ирц, үр дүнгийн түүх
9. Төлбөрийн төлөв, данс хуулах
10. Профайл, тохиргоо, бүртгэл устгах хүсэлт

### 4.3 Техникийн бүтэц
```
mobile/                      ← одоогийн репод шинэ хавтас
  lib/
    api/        ← NestJS Swagger-оос автоматаар үүсгэсэн Dart клиент
    data/       ← drift (SQLite): бодлого, даалгаврын офлайн кэш
    features/   ← login, home, homework, exam, books ...
    ui/         ← дизайны систем: үндсэн хөх + цагаан, lucide иконууд
  test/         ← widget, golden (томьёоны зураг) тестүүд
```

| Хэрэгцээ | Сан |
|---|---|
| Төлөв (state) | Riverpod |
| Навигаци | go_router (буцах = өмнөх хуудас) |
| HTTP + JWT шинэчлэх | dio |
| API клиент | `openapi-generator` → манай `api/src/swagger.ts`-ийн OpenAPI-аас |
| Офлайн сан | drift (SQLite) |
| Push | firebase_messaging (FCM, iOS-д APNs түлхүүрээр) |
| Нэвтрэлт | google_sign_in, sign_in_with_apple |
| Камер, зураг | camera / image_picker + flutter_image_compress |
| Иконууд | lucide_icons (веб-тэй ижил, emoji хориотой дүрэм хэвээр) |

**API-ийн давуу тал:** манай API аль хэдийн `@nestjs/swagger`-тэй. Түүнээс Dart клиентийг
автоматаар үүсгэвэл API өөрчлөгдөх бүрт апп-ын код автоматаар таарна.

### 4.4 Хамгийн хэцүү хэсэг — LaTeX томьёо
Манай 12,800+ бодлого бүгд LaTeX. Flutter-т харуулах гурван арга:

| Арга | Хурд | Зөв харагдах | Тайлбар |
|---|---|---|---|
| A. `flutter_math_fork` | Хамгийн хурдан, натив | KaTeX-ийн ихэнх нь, бүгд биш | Дэмжихгүй командууд дээр алдаа гарна |
| B. Сервер дээр SVG болгох | Хурдан (кэштэй) | **Веб-тэй 100% ижил** | API KaTeX/MathJax-аар SVG үүсгэж кэшлэнэ, апп `flutter_svg`-ээр харуулна |
| C. WebView-д KaTeX | Удаан, гацдаг | 100% | Гөлгөр байх зорилгод харшилна |

**Зөвлөмж: A + B.** Энгийн томьёог A-аар шууд зурна. A дэмжихгүй томьёог урьдчилан
илрүүлж B (SVG) руу шилжүүлнэ. Үүнийг тодорхойлохын тулд **бүх 12,800 бодлогыг автомат
тестээр A-аар зурж үзэж**, бүтэлгүйтсэнийг жагсаана (golden test).
Энэ нь «AI runtime-гүй» дүрэмтэй адил: бүх ажлыг урьдчилан хийж санд хадгална.

### 4.5 Бусад хэцүү хэсэг
- **MathLive** (`web/src/components/tools/core/MathInput.tsx`) — зөвхөн хэрэгслийн хуудсанд.
  Сурагч ихэвчлэн A–E сонгодог тул эхний хувилбарт хэрэггүй. Дараа нь Flutter-ээр өөрийн
  математик гарыг `math_keyboard` сан дээр суурилж хийнэ. Photomath шиг зураг дарж бодох: [MOBILE-SCAN.md](MOBILE-SCAN.md)
- **three.js** — зөвхөн нүүр, маркетингийн хуудсанд. Аппад хэрэггүй
- **Хуваарь, гараг** — веб-ийн «эзэн МОНГОЛ 1=Даваа, ӨС JS 0=Ням» урхи Dart-д ч бий
  (`DateTime.weekday` нь 1=Даваа…7=Ням) — нэг хөрвүүлэх функц, тесттэй
- **Хоёр газар арчлах** — шинэ функц веб, апп хоёуланд нь. API-г нэг байлгаж, бизнесийн
  дүрмийг бүгдийг серверт үлдээвэл апп зөвхөн «харуулах» үүрэгтэй болж ачаалал багасна

### 4.6 Гөлгөр байдлыг баталгаажуулах
- Жагсаалт бүр `ListView.builder` (зөвхөн харагдаж буйг зурна)
- Томьёоны зургийг кэшлэх, зургийг жижгэрүүлж ачаалах
- `flutter run --profile` + DevTools-оор хуучин, хямд Android утсан дээр хэмжих
  (сурагчдын утас ихэвчлэн хямд — хамгийн сул утсан дээр 60 fps байх ёстой)

### 4.7 Build ба хүргэлт
- Android: энэ Mac эсвэл CI дээр
- iOS: **зөвхөн macOS + Xcode** (энэ Mac эсвэл Codemagic / GitHub Actions macOS runner)
- TestFlight (iOS) + Play internal testing → багш нар, 10–20 сурагч → дэлгүүр

### 4.8 Үе шат
| Үе | Агуулга |
|---|---|
| F0 | Төсөл, дизайны систем, API клиент үүсгэх, нэвтрэлт |

## 6. Эцсийн зөвлөмж (эзний нөхцөлд)

1. **Одоо:** PWA-г дуусгах (бараг бэлэн) — сурагчид шууд ашиглана
2. **Capacitor-ийг алгасах** — гөлгөр байдал зорилго тул
3. **Flutter:** сурагч + эцэг эхийн апп, F0 → F6. Эхлээд F1 (LaTeX) — энэ нь хамгийн
   том эрсдэл тул эрт шалгаж баталгаажуулна
4. Багш, админ веб хэвээр; бизнесийн дүрэм бүгд API-д
5. «Шинэ ирээдүйн эзэд» нэрээр D-U-N-S авах ажлыг одооноос эхлүүлэх (хамгийн удаан хүлээдэг)
